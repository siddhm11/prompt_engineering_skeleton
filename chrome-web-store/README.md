# Prompt Memory: Chrome Web Store kit

Everything the Developer Dashboard asks for when publishing **Prompt Memory
4.6.2**: images, video, listing text, privacy answers and reviewer notes,
plus the scripts that made them.

Every product image and video frame is the **real extension**
(`extension/`, loaded unpacked) running on the **live** chatgpt.com,
gemini.google.com, perplexity.ai and grok.com, captured in Chromium on
2026-09-24. Two things were staged; see "What's real" below.

```
chrome-web-store/
├── README.md                      ← you are here
├── listing/
│   ├── store-listing.md           name, summary, description, category, URLs
│   ├── privacy-practices.md       single purpose, permission reasons, data-use ticks
```

## Before you submit: blockers

1. **Prompt tracking default contradicts what users are told.** Three
   user-facing texts say it starts off: the privacy policy (*"Prompt Tracking
   is OFF unless you turn it on"*), the first-run data notice in
   `content.js` (*"logs submitted prompts only if you turn it on"*) and the
   popup (`popup.html:611`, *"starts off and requires you to switch it
   on"*). Since commit `f8d0b96` (Sep 18) the code does the opposite:
   `content.js:119` and `:130` treat a missing `pm_tracking` as **on**, so a
   signed-in user's submitted prompts are logged from the start. Google
   compares the policy, the privacy form and the behaviour, so this is the
   most likely rejection reason. Pick one:
   - **Recommended:** default it to off again (`pm_tracking === true`). That
     matches the policy, the consent notice and the listing, and avoids
     declaring a passive "User activity" collection the rewrite feature
     doesn't need. (Tracking also records nothing on ChatGPT and Claude
     today, because ProseMirror fires no `input` events.)
   - Or keep it on and update `website/privacy.html`, the first-run notice
     and `listing/privacy-practices.md` to say so plainly.
2. **In-extension privacy links point to GitHub source**, not the policy
   page: `popup.html:615` and `content.js:3973` link to
   `github.com/…/blob/main/website/privacy.html`. Point both at
   `https://prompt-engineering-skeleton-seven.vercel.app/privacy`, the URL
   the dashboard will list. If the repo is private, those links 404 for
   reviewers today.
3. **Rebuild the ZIP after any change**: `python3 scripts/package_extension.py`
   writes `dist/prompt-memory-<version>.zip`. Bump `version` in the manifest
   for every upload after the first.

## What's real, what's staged

- **Real:** every pixel of the extension UI (⊕ pill, card, style buttons,
  version stepper, `//` menu, library sheet, privacy sheet, popup) and the
  host sites around it, all logged out. Clicks and typing were real input
  events.
- **Staged:**
  1. **The rewrite text.** The model's reply was served from a script
     (`tools/capture.py` holds each example), written to follow the
     product's Deep, Quick and Creative instructions. It was not generated by
     Groq.
  2. **The demo account's library.** The six saved prompts come from a
     stand-in server (`tools/stage.py`), because signing in with Google
     can't be automated.

Store policy asks that screenshots represent the item accurately. The UI
is real, and the rewrites are representative, but you can make the text
genuine with one command using your own key. The key is read from a file, so
it never lands in shell history:

```bash
# once: put a Groq key in a file only you can read
printf '%s' 'gsk_…' > ~/.pm-demo-key && chmod 600 ~/.pm-demo-key
cd chrome-web-store/tools
uv run --with playwright --with pillow --with imageio-ffmpeg sh -c '
  python -m playwright install chromium &&
  PM_LIVE_KEY_FILE=~/.pm-demo-key python capture.py && python compose.py &&
  PM_LIVE_KEY_FILE=~/.pm-demo-key python record.py && python build_video.py'
```

Live model text varies in length, so look over the five screenshots
afterwards.

## Step-by-step: from here to "Published"

1. **Developer account** (one time) at
   <https://chrome.google.com/webstore/devconsole>: pay the US$5
   registration fee, turn on 2-Step Verification for the Google account,
   verify the contact email (`hello.promptmemory@gmail.com`), set the
   publisher display name, and make the **trader / non-trader declaration**
   (EU Digital Services Act). A free, non-commercial project is usually
   *non-trader*.
2. **Fix the blockers above**, run the checks you normally run
   (`scripts/check_*.py`), rebuild the ZIP, and load that exact ZIP unpacked
   in a clean Chrome profile once.
3. **New item → upload the ZIP.**
4. **Store listing:** paste the text and upload the images from the upload
   map.
5. **Privacy practices:** paste the single purpose and the justifications,
   tick the data types, certify, and add the policy URL.
6. **Distribution:** Public (or Unlisted), all regions, free.
7. **Test instructions:** fill the placeholders (review-only Groq key, a
   disposable Google account without 2-Step Verification) and paste.
8. **Submit for review.** Broad host permissions on five chat sites plus
   three API hosts usually mean a longer, in-depth review (days, sometimes
   a couple of weeks). Keep the HF Space awake, or rely on route A in the
   test instructions.
9. **After approval:** revoke the review key, put the store link in the
   website, the GitHub README and the YouTube description, and use
   `clips/*.gif` in the README.

## Also worth knowing

- **Claude isn't in the images.** claude.ai redirects logged-out visitors to
  its login page, so an automated capture can't reach its chat box. The
  extension does support it. For a Claude shot, give `Stage` a persistent
  `profile=` folder, sign in to Claude once in the window it opens, and
  reuse that folder for the Claude scene. Or take one by hand at 1280×800.
- **The shipped icon has an opaque light square behind the tile**
  (`extension/icon128.png` has no transparency), which shows as a pale box
  on dark backgrounds. `images/icon/store-icon-128.png` is the same design
  redrawn in vector, with Chrome's recommended 96 px art and 16 px
  transparent padding. `images/icon/extension-icons/` is an optional
  drop-in replacement for the manifest icons.
- **Names of other products.** Naming ChatGPT, Claude, Gemini, Perplexity and
  Grok to describe compatibility is fine. The description ends with a
  non-affiliation line; keep it. Don't put their logos in the tiles.

## Regenerating (future versions)

```bash
cd chrome-web-store/tools
uv run --with playwright --with pillow --with imageio-ffmpeg sh -c '
  python -m playwright install chromium &&
  python capture.py     # raw 2x screenshots of the real extension on the live sites
  python compose.py     # → ../images (screenshots, tiles, icon)
  python record.py      # screencast of the demo flows
  python build_video.py # → ../video and ../clips'
```

`capture.py` and `record.py` open visible Chromium windows: ChatGPT and
Perplexity show a Cloudflare check to headless browsers. Each scene uses a
fresh profile, so no draft leaks between scenes. Raw captures and frames
go to `tools/raw`, `tools/crops` and `tools/video`, which git ignores.
